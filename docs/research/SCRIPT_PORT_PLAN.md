# Script_Game.dll port plan

Companion to `SCRIPT_ENGINE_INTERFACE.md` (the host API) and the rule docs (`GAME_RULES.md`, `COMBAT_AI_RULES.md`, `GAME_LOGIC_MAP.md`). Written 2026-10-20 from a full Ghidra 12.1.4 decompilation of `scripts/Script_Game.dll` (build 1.75.20108.14). The decompiled bodies live only in the gitignored `.local/research/script_game/` (one `.c` file per function under `<category>/<name>.c`, plus `index.json`); this document contains my own prose, names and numbers only.

Evidence tags follow the rule docs: **[V]** read from code, **[I]** inferred, **[U]** unknown. Coverage means "an existing rule doc cites this function by `S:` address (`address`) or mentions its registry name (`name`, weaker: the doc may only list it)". It does not mean a Rust port exists or is verified; `crates/sim` currently implements a subset (see `crates/sim` and `SCRIPT_ENGINE_INTERFACE.md` section 3).

### Script ABI observed in the decompilation [V unless marked]

- **Resumable states.** A `ZS_*`/`PS_*` state body is called repeatedly with `(state stack, processing unit)`. Each blocking step has a lazily allocated static slot id; the function compares it with the progress counter stored in the top stack frame (frames are 0x18 bytes, `gScriptRunTimeSingleState`) and either skips the step as already done or queues one AI command and records progress [I: reading of the compare-and-store pattern; seen in `ZS_Smith` and all routine tasks]. Routine tasks additionally keep a `TaskPosition` counter in `PSRoutine`, incremented per pass and used as a `switch`. In Rust model every state as `fn step(&mut self, ctx) -> StepResult { Yield(cmd), Done, Goto(state) }` over an explicit step enum rather than trying to re-create the slot trick.
- **State transitions** are explicit host calls: `PSRoutine::SetState` (256 call sites) and `SetTask` (138), `ContinueRoutine` (116). Script-to-script calls go through `RunScriptFunction` by name (615 sites). A port needs a name-to-function table; `.local/research/script-registry.json` already enumerates it.
- **Callbacks** (`On*`) are plain functions invoked by the engine on animation events, damage, enter/leave areas and ticks; their signatures are the `ScriptCtx` surface (batch B14).
- **Use-type object table.** `S:8190` returns, for a `gEUseType` value, the interaction-object entity currently found for the NPC from a global table of `Entity` slots (filled by the scanner `S:7c90`). Routine tasks use it to get their work object: `ZS_Smith` asks for use types 0x39 Anvil and 0x3a Forge, `ZS_Digger` for 0x56 WaterBarrel [V id mapping via `gEUseType`, I table fill]; a `None` result sends the NPC to an idle fallback task.

## 3. Port order and batches

## 4. Batch details

### B00: Shared helper library

- **Scope:** 123 shared helpers, 29799 bytes. Cited by address in docs: 5.
- **Rule-doc sections citing these by address:** COMBAT_AI_RULES §2.12 (2), COMBAT_AI_RULES §2.10 (1), COMBAT_AI_RULES §9.5 (1), COMBAT_AI_RULES §9.3 (1), COMBAT_AI_RULES §10.5 (1).
- **Host API used (Script/Game/Engine dll classes by call sites):** Entity 813, PSInventory 118, PSNpc 70, Template 50, PSRoutine 35, eCApplication 25, PSInteraction 15.
- **Behaviour:** Not a gameplay module: the 123 non-registered helper subroutines that are reached from more than one batch. They fall into four groups: (1) typed wrappers over script-global lookups: the indexed global-entity table, class-name unmangling and module-admin lookups, used by almost every state; (2) growable-array and string plumbing instantiated for `Entity` and `bCString` (about 20 tiny functions: grow, copy, free); (3) gameplay helpers shared across modules: the hand-item-combination to weapon-mode lookup (`S:2dd0`, `S:3240` family, documented in COMBAT_AI_RULES 2.12), the animation-speed multiplier (`S:42a0`, the largest helper at about 2.9 KB, COMBAT_AI_RULES 9.5), weapon-slot and use-type probes over `PSInventory`/`PSInteraction`, SVM sample-name formatting (`S:baf0`, `S:bc20`), and the player-is-owner/target predicates (`S:79a0`..`S:7c90`); (4) AI-state bookkeeping used by routines (`S:1d90`/`S:1e20` write the routine's AniState property). Port these first as a `helpers` module behind the host traits; most are 10-150 bytes and become one-line Rust functions. The array/string plumbing disappears in Rust (`Vec<Entity>`, `String`).

Design summary:

* `host.rs` defines the engine interface the ported code needs (`ScriptCtx`, `EntityApi`, `NpcApi`, `InventoryApi`, `StatsApi`, `WorldApi`, `CombatApi`, combined as `ScriptHost`). `crates/sim::script_host::SimHost` implements all of them over a `&mut Sim<W>` (positions, line of sight and field of view through the simulation's `WorldQuery`, stats, party and enclaves from the actors and game state, routine bookkeeping in `Sim::script`); AI commands queued by script states are collected in `Sim::script.commands`; `crates/sim::sim::ai_exec` executes the combat ones (swing, parade, jump, goto, wait, shoot, potion) and runs the callbacks, see the combat design below.
* Every `ZS_*` task body is data: `routine::work::definition(State)` returns a step table or a custom function; one interpreter (`run_state`) runs them with the DLL's compare-and-store semantics (one AI command per call, step counter in the host). `Variants::fast_routines` is the DLL's debug byte; `EngineSetup` carries the `ge3.INI` flags (shipped values by default).
* **Combat design (B08-B10).** `combat::definition(State)` extends `routine::work::definition` with the attack, reaction and arena states, all as step tables over the same interpreter. `run_state` is called whenever the actor is idle; a movement instruction (`AiCommand::CombatGoto`, `GotoExt`) installs a *local callback* (`OnAttack_Goto`, `OnFlee_GoBack`, ...) that the host runs every tick (`combat::run_callback`) and that ends the movement by changing the state; *task callbacks* (`OnReactToWeapon`, `OnArena`, ...) run every tick whatever the actor does. The simulation keeps `Task::Attack/Flee/Threaten/ReactToWeapon/Reaction` as mirrors of the script task (`reflect_script_task`), so every fight, flight and warning of `Sim` is now driven by the ported states; the simulation only supplies motion (speeds, hit windows from `combat::commands`, stamina) and the parry/damage pipeline of B07. `SelectCombatMove` is `combat::select::select_combat_move`; the weighted move choice of humanoids (`combat::moves`) keeps the DLL's `CanDo`, situation snapshot, the 12 jump tables of the score and the shortlist bookkeeping.
* `crates/sim::routine` now delegates `GetRoutineTime`, the use-type task table and the species mapping to `gothic-script`; its `RoutineTask` enum, the `RoutineResolver` hook and the tests are unchanged.

### 8.1 Corrections to the rule docs (behaviour changed in `gothic-script` and, where noted, in `crates/sim`)

1. **Orc <-> Assassin attitude** [V `GetPoliticalAttitude`, S:f620]: the matrix cell is not "friendly from chapter N". 6. **`CanSleep`, `CanThreaten`, `CanEatGround`** [V]: plan B02 called three of them stubs; only `CanSwim` returns false unconditionally. The other three are species tables (ported verbatim into `predicates`).

### 8.3 New facts about the routine tasks (all [V] unless marked)

* **Work-station shape.** Each dispatcher (`ZS_Smith`, `ZS_Alchemy`, ...) picks an object, sets the task callback `OnGoto`, queues `_AI_Goto_Ext`, and after arrival sets `OnWork` and switches by the destination point's use type to a sub-state. Dispatchers with several candidate use types choose **randomly among the objects the scanner found** (Alchemy: Alchemy/Bookstand/Cauldron; Study; Trader: Trader/Bookstand/Bookshelf/Chest/CleanFloor; Woodwork; Boss; SlaveBabe; OrcParty; Break; Herd; Goblin); the others use the routine's current destination. No object means `ZS_Idiot` (Break: `ContinueRoutine`, Herd: `ZS_Herd_EatGround`).
* **`ZS_Smith` cycles** through `PSRoutine.TaskPosition`: Forge, Anvil, Forge, Anvil, WaterBarrel (cooling). Missing Anvil aborts to `ZS_Idiot`; missing Forge/WaterBarrel skips the pass. Anvil/Forge states end with `SetState(ZS_Smith)`; Cool ends with `ContinueRoutine`. They assure `It_Hammer_Smith` + `It_Sword` (created if missing) and hold them. Smith needs no free-object search beyond the scanner.
* **Durations.** `rand(31) + 30` s ("medium": Alchemy, Cauldron, Farmer, Break water, Digger barrel, Study shelf, ...), `(rand(3) + 2) * 60` s ("long": Anvil, Digger, Lumberjack, Waterpipe, Cook/Grind/Barbecue/Bard via `S:76b0`), `rand(11) + 10` s (Break chest/barrel), fixed 10 s (Pee, Cool), fixed 5 s (Boss pace). Ambient creatures idle `rand(11) + 10`, others `rand(31) + 30` (`S:76e0`). The DLL's debug byte makes every one of them 10 s.
* **Endings.** Most work states end with `HaveABreak` (`S:8c390`): an NPC whose point belongs to an anchor continues its routine, a free-standing one takes a `ZS_Break`. Break sub-states: Stool/Bench/SitGround/Stand smoke an `It_Joint` for `rand(11)`, Pee 10 s, Chest kneels and opens, WaterBarrel drinks.
* **`ZS_HangAround`** dispatches Stool/Bench/Waterpipe/SitGround/campfire (coin toss between frying meat and sitting)/Smalltalk (partner search pairs both NPCs into `ZS_Smalltalk`, else `ZS_HangAround_DoNothing`)/default Stand; without a destination it walks to a random free Bench/SitGround/SitCampfire/Stand object.
* **Sleep.** `ZS_Sleep` registers `OnSleep`, lies down on Bed or SleepGround, `ZS_Sleep_Loop` polls every 60 s of state time: it keeps sleeping while the dialog page is open with the NPC, otherwise wakes (voice line `Awake`, `ContinueRoutine`) once `GetRoutineTime` is not sleep. Animals use raw AI mode 7 (unnamed in the reflection data) and the `OnAnimalSleep` callback; `ZS_AnimalSleep_SleepGround` re-checks every 60 s.
* **Ambient** creatures wander to a random navigation point `rand(200) + 200` (ambient species) or `+ 300` (others) from their start position, Pig and Cow never wander, a Bloodfly in water holds `Fist` and does not sleep on water; the idle action is `GetAmbientAction` (EatGround 80 percent for Scavenger/Bison/Rhino/Pig, 50 percent for Boar/Deer/Cow, else Ambient).
* **Guards** stow both back-slot weapons, register `OnGateGuard` as local callback when `IsGateGuard`, idle with a long `Ambient` action. **Preach** uses voice lines `Speech_00..09` when the NPC has them, else a long `HandsOnHips`. **Pray** kneels at a `Shrine`. **OrcParty** has drum (two `It_DrumStick`), dance, boulder tilt/hold/lift and spectator (`ArmsCrossed`).

2. **AI mode 7** is `Sleep` (animals asleep) and **11** `PlayerParty` (companions); the simulation's `AiMode` has neither, the adapter keeps them in `NpcScript::extra_mode`. `CanReceivePerceptionFrom` lets sleepers be perceived only with the wake flag.
3. **`AssessTarget`** [V]: Panic or `!CanAttack` (ambient creatures, Deer, Pig and Cow cannot) means `ZS_Flee`; otherwise reason, crime (Theft/UseInteractObject give Theft, Murder gives Murder), enclave notification (ReactToDamage mode 3, Enemy mode 2), combat-group state, alert of the target (`AssessAttack`) and `ZS_Attack`. A dead witness is put back into `ZS_Dead`.
4. **`CallHelp`** (S:332e0) [V]: does **nothing when the caller's own attack reason is StopThief, Theft or UseInteractObject** (the rule doc had it the other way round); otherwise friendly guards within 10 m of the culprit that are not friendly toward it attack with reason StopThief.
5. **Perception ranges** [V constants]: sneaking, drawn weapons and thefts are noticed within 700 (sneaking, weapon) and 1000 (theft); a sleeping animal wakes within 1000 (500 when the player sneaks, never with `Perk_Sneak_2` while sneaking or in `PS_Ranged`); a sleeping human wakes for an audible (not sneaking and moving) player within 500 who is in clear view. `AssessPlayerWeapon` also exempts companions dismissed within the last second.
6. **`GetAttitude`** [V structure, I some operand roles]: `None` for the player as observer; friend-types mirror how the target stands with the player; flight from the target is Panic; outlaw (Out vs non-Out, non-Pirate humanoid) Hostile; revolution; party leader relation Friendly; Controlled members Neutral to humanoids; toward the player `GetAttitudeToPlayer` (wanted-by-faction Hostile, boss/guard by fame and enclave crime, own crime memory, lost/cancelled fights Angry); political matrix; species. The enclave pardon changes any status except Attack: fame 100, crimes cleared and members reset; Flee also counts one political crime against the player outside the enclave "Ardea" (the rule doc had it inverted).
7. **Parry predicates** [V + U]: `CanParadeMoveOf` (S:d640): fist fighters only parry fist fighters; Pierce and Hack (and with `AIMode` Power) can only be parried with sword and shield. `IsInParadePose` needs primary pose 2 for sword and shield, 1 or 2 for dual/torch pairs and 1 otherwise [U: the second and third hand pairs are guesses]. `HasStaffMagicParade`: staff in the right hand plus `Perk_StaffMagic` (player) or Mage class.
8. **`AssessHit`** [V]: reproduced step by step from COMBAT_AI_RULES 2; the differential test against `crates/sim` agrees for melee hits of both sides and every move multiplier. One difference is deliberate: the port reads `Level`-dependent stats through `CurrentLevel = min(GetLevel + Level, GetLevelMax)` (see 8.2), so `crates/sim` now does the same (`SimConfig::current_level_adds_raw`, default on); the Ardea orc raider (Level 10, LevelMax 30) now hits for 58, not 47. Set the flag off to get `min(GetLevel, LevelMax)`.
9. **Protection** in `crates/sim` was corrected to the port: Blades/Impact are divided by 5, Missile/Lightning/Fire/Ice are not, Fire/Ice get +10 with `Perk_ResistHeat`/`Perk_ResistCold`.
10. **Kill/Defeat** [V]: Kill stamps the fight, resets effects, drops hand items, sets AI mode Dead, dissolves the party, prints `GO_GameOver` for the player, tells the quest manager, applies the Talchef retaliation (mine NPCs get routine `Mine_Attack`), pays XP once, clears the destination and regenerates plunder (a Demon keeps nothing). Defeat is the same with AI mode Down, the Attack crime (only for the player against non-guard, non-boss, non-duel/arena victims) and `LastFightAgainstPlayer = Lost`. `ZS_Unconscious_Loop` regenerates 10 hit points and stamina per second (15 hit points after an arena defeat) and wakes after 5 s (player side), 20 s (arena) or 30 s unless a dialog is open.
11. **XP** [V]: `GiveXP` as in the rule doc; unrolled level-up check replaced by a loop; `XPNext(L) = 250 (L + 1)(L + 2)`.
12. **Companions** [V]: follow distance `(rank + 3) * 150` where waiting companions and those in `ZS_WaitForPlayer` do not count (500 unranked); a mob member 620 m from the "Fireclan" enclave is dismissed with the line `TooFarFromMeetingPoint`; a swimming or diving player sends companions to `ZS_WaitForPlayer`; guides wait when the player is more than 10 m behind and resume within 8 m.

Still unresolved after round two: the third `SelectRoutineTask` branch, `GetRevolutionAttitude` (S:ea50), the first-argument order of the inner call in `GetFocusNameAttitude`, the exempt entity names in `GetPoliticalAttitude` (Orc vs Ass), `Level` versus `LevelMax` data semantics (real world NPCs mostly have `Level` 0, `LevelMax` > 0; a 0 gives `CurrentLevel` 1 under both readings), `NotifyEnclave` modes 2/3.

### 8.6 Findings of the third round (B08-B10, the rest of B06 and B12)

Evidence tags as above. The script port is authoritative; where it disagrees with `COMBAT_AI_RULES.md` section 9 the port wins.

1. **Move selection is a score table, and the "level percent" is not part of it** [V S:67c0, S:6560, S:63c0, S:57d0]. `SelectCombatMove` -> `FAI_Active` -> (weapon species) `S:67c0` scores the 15 candidates in the fixed order Fwd, TurnL, TurnR, Pierce, Power, Whirl, Hack, SimpleWhirl, Attack, Quick, Parade, JumpBack, Left, Right, Back. The score (`S:57d0`) starts at 0, -35 for a repeated move or an attack within 3 s of the last strike (`CanHit(30)`), and adds 45/55/65/70/75 or the aggression weight `W` by a 12-table decision tree over: opponent mid-attack, in reach of its attack, the player facing me, line of sight, "inside my attack range minus 25", engaged one-on-one versus crowd, and the opponent's current action. Out of melee range only `Fwd` scores (85; against a mage `Back` 85 when a crowd attacks and backing off is possible). Moves score only if `CanDo` (`S:4f80`) allows them. `S:6560` keeps moves above `W` within 35 of the best in a descending list and the weaker ones in a secondary list; `S:63c0` rolls `Random(55) < W` once per decision: on a hit the secondary moves join the front at the best score; the move list is cut to `max_keep` (3, raised to 12 or 4 by the branch) **without trimming the score list** (the pairing shifts, replicated); the pick is uniform over a bag where the best score counts 3, the lowest 1 and the rest 2. The doc's "level percent chance of the optimal move" belongs to `S:6e60`/`S:7030` (offensive-only/defensive-only pickers, `p` = `GetLevelMax`, Zombie 85, -10 easy, +10 hard); the DLL calls them without taking the situation snapshot first, so they always return nothing and `FAI_Passive` is effectively the range rule (back off below 3.5 m, approach beyond 4.5 m, else turn). A consequence: the old simulation constant `combat_skill_pct` has no counterpart; skill is `W` (5, +20/+10/0 by difficulty, level 1 minimum 20, -5 above level 30 and again above 70, -10 arena, -5 mage opponent, -10 companion) and the move tree.
2. **`CanDo` corrections** [V S:4f80]. Attack moves (ids 1-6, 9-11, 14) need `CanHit(MinHitDuration)` for every NPC. Humans, Skeletons, Zombies and Orcs **never jump back** (JumpBack is for monsters that can evade); Left/Right/TurnL/TurnR need the species to be able to sidestep (`S:1fa0`: humanoids, Varan, FireVaran, Bloodfly, Ogre, Golem types, ScorpionKing, Stalker) plus `CanEvade` toward that side, and the turns additionally exclude Troll, Golems and Goblins. Parade is limited to Human, Skeleton, Zombie, Orc and Minecrawler and fails against an opponent already in the parade pose or one whose move `CanParadeMoveOf` says cannot be blocked. Whirl and Pierce are foot-fighter moves (`{0,1,2,5}`): Whirl needs a two-hander/staff/axe/halberd in the right hand, Pierce a one-hander, Hack a two-hander or a swing tool, the simple whirl a one-hander in each hand. Quick attack: not with bare fists for humanoids; always for the listed monsters.
3. **`ZS_Attack_Goto` has no close-range precondition** [V asm]. The decompiler nested the whole body under `GetCloseRange < distance`; the instructions show that comparison only guards a lazy static string initialisation. The approach is unconditional and ends through its callback; `GetCloseRange` (500, 600 for Troll/Trex/Dragon) has no observable effect.
4. **`OnAttack`** (S:147c0) [V]: target gone, dead or down -> `ZS_Attack_End`; target talking -> `WaitForDialog`; Intruder against the player unless the zone is angry -> `WaitForFlee`; Arena reason with a stopped arena -> "YouLeftTheArena"/`GO_ArenaWarning`/`Arena_End`; DriveAway more than 8 m from the alternative target -> `ZS_EatBody`; a swimming/diving target -> `WaitOnShore`; unless the reason is Prey, DriveAway, Duel, Arena or Kill a better target found by `S:a070` is attacked (ReactToDamage, Enemy for Hostile, Prey for Predator, Revolution stays). `StatePosition` gates it (about once per move). Movement callbacks: strafe and turn end after 0.6 s, go-back re-selects every 0.4 s, positioning ends below 5 m or after 1 s, the approach re-selects every tick and stops for any other move.
5. **`ZS_Attack_End`** [V S:1a610]: finishing blow (`HasAttackReasonToKill`, `CanDo(Finishing)`, `CanBeKilled`); a second enemy is taken on; a fight where the opponent's attacker is the player sets `LastFightAgainstPlayer = Friendly`, one the NPC won against a downed or dead player sets `Won` (both stamp the time; **there is no "Lost" write here**, that is `Defeat`); stand up, holster (not for Bloodflies); a Summoned creature is killed; the winner ransacks if `WantToRansack`, else waits 2 s and `ContinueRoutine`.
6. **Combat commands** [V]: the `_AI_*` attack commands set `Action`, `AniState`, `HitDirection` and `StatePosition`, charge the stamina with `AddStaminaPoints(-n)` (12/10, 20, 20+20 hack, 40 whirl; `JumpBack` free with ExtendedContent; a pierce out of the parade pose pays nothing) and register the `OnAI_*` callback that switches the damage strip on after 0.25 s (plain, simple whirl, whirl, get-up parade), 0.1 s (quick, power, sprint, get-up attack) or 0.8 s (pierce); a finishing blow takes 1.2 s; the guard of a parade ends after 0.5 s. These numbers are the single source for the simulation now (`vitals::stamina_cost/hit_window_secs` delegate).
7. **Reaction timers and outcomes** [V]: `ZS_ReactToDamage` says "WhatAreYouDoing", polls (`OnReactToDamage`: target farther than 7 m, 30 m for archers and mages, or 10 s task time ends it) and keeps within 5.5 m; the end turns into `ZS_WatchFight` when anybody still fights the target. `ZS_ReactToWeapon`: voice "WeaponDown"/"StopMagic" (or "LookingForTroubleAgain" after a won fight) with a warning broadcast, second warning at 4 s, attack with reason ReactToWeapon (6) at 8 s, a lowered weapon ends in "WiseMove" and `ZS_ObserveSuspect` (so after a warning the guard **keeps watching the suspect** instead of returning to work at once; the simulation and `tests/crime.rs` now follow that). `ZS_ReactToZone`: "GetLost", at 4 s "ISaidGetOutOfHere" (when the zone is guarded), at 8 s attack with reason Intruder. `ZS_Threaten`: attack (reason Angry) below 7 m or after 5 s, give up beyond 10 m. `ZS_Flee`: "RunAway"/"RunRevolution", `ResetAll`, run to the nearest flee point (use type 115), look again every 0.5 s: at the point (5 m) with the pursuer still there flee again, without one watch the follower; beyond 20 m keep watching; with no flee point walk home and watch the pursuer from 20 m.
8. **`GetGuardAttackReason`** [V S:3d050, resolves a doc gap]: a guard that knows a murder attacks with reason **Revolution (19)** (to kill, and the enclave is told: `NotifyEnclave` mode 1), a theft with reason Theft, anything else none. `_AI_Excuse` needs `Perk_Excuse`; crimes up to Attack always work, murder and theft roll `Random(130)`: above 117 or above the Theft skill fails; failure: "IDontBelieveYou" and the attack above. `PickPocket`: victims of `LevelMax` below 30 can be tried by anybody, 30-44 need `Perk_PickPocket_2`, 45-49 `Perk_PickPocket_3`, 50 and up are "Impossible"; the chance is `85 + Theft/2 - LevelMax` percent; a failure is attacked with reason Theft; a success counts one theft for the victim's enclave unless ExtendedContent and `Perk_MasterThief`.
9. **`CurrentLevel` resolved** [V code, I data]. The assembly of `GetCurrentLevel` (S:36b40) is literally `min(GetLevel(e) + PropertyLevel(e), GetLevelMax(e))` for NPCs (the player returns his raw level). Nothing in the script DLL writes an NPC's `Level` (only `GiveXP` and `TransformBack` write the player's), `gCNPC_PS::SetLevel`/`SetLevelMax` (Game.dll S:4e30/4e60) have no direct callers, and the world data carries `Level` and `LevelMax` per NPC (10279 NPCs: 4911 with both set, e.g. the Ardea raider 10/30; 2200 with `Level` 0, e.g. slaves 0/10; 3168 with both 0). So `Level` comes from the entity/template data only and the double addition is the real behaviour: the raider is level 20 on normal difficulty (30 on hard, 11 on easy), a `Level 0` NPC is level 1 whatever its `LevelMax`. **`current_level_adds_raw` stays on (default true)**; the flag only exists to compare with the alternative reading. The aggression weight reads the *raw* `Level` property exactly as the DLL does (`S:74e0`), the picker skill the difficulty-shifted `GetLevelMax`.
10. **Fight scenario** (`crates/sim/tests/fight.rs`, level-1 hero with a one-hander against the Ardea raider): before (rule-doc tactics) the raider won 40 of 40 synthetic duels in 15.4 s on average; with the ported combat AI it wins 40 of 40 in 12.5 s (real data, 100 seeds: 100 of 100, 11.9 s), the hero is hit about 4 times and parries about once per fight. Against a weak level 3/5 orc the hero now wins 38 of 40 (before 29-34). The raider uses Attack, Power, Quick, Whirl/Hack/Pierce (by the weapon class), parades when the hero swings, approaches via `ZS_Attack_Goto` with callback hand-over, and returns to its routine after the fight.
11. **Open points after this round** [U/I]: the animal branch of `FAI_Active` (long probability tree behind the species test; reconstructed from the documented behaviour: sprint at the player, power attack or bite in reach, run in otherwise), `FAI_Magic`/`FAI_Misted` ordering, the fine structure of `AssessFightSound`/`AssessMurder`/`AssessDefeat` (attitude case tables), `S:a070` (target search, 2.7 KB filter chain: reconstructed as the nearest awake dry hostile NPC within 25 m that fights the searcher), `S:14f0` (front-line admission: fewer than 1 (2/3 against the player on normal/hard) attackers per target), the ObserveSuspect loop clauses, the unit of the `LastHitTimestamp`/`CanHit` clock (taken as 100 ms; `SetLastHit` stamps the NPC's own strike, `SetLastHitTimestamp(0)` from `AssessHit` lets a power-hit victim answer at once), whether the engine clears `PSRoutine.Action` after a move (the simulation does for engine-set actions only), `GetCombatMoveLength` for monsters beyond the table.
